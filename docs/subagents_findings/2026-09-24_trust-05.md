# TRUST-05 (#261): junit all-passed guard for every RLS proof step

Epic: #256 EPIC-TRUST-01. Base: 4f74c0f.

## Expected vs actual

- Expected: the `RLS Proof` job fails whenever any of its proof tests did not run to PASSED, as its header ("fails closed") claims.
- Actual (base): only the Postgres ledger step had a guard (GH-04's inline heredoc). The RLS deny step and the multi-process SQLite ledger step checked nothing but pytest's exit code. `tests/dms/test_rls_blocks_out_of_scope_read.py` skips as a whole when `DMS_LEDGER_DSN` is empty, and pytest exits 0 when every test is skipped, so that step could go green having proved nothing.

## Root-cause class

Gate honesty: a CI step trusted a process exit code that does not distinguish "proved" from "did not run". Skip is not pass.

## Fix

- `scripts/check_junit_all_passed.py --junit PATH --expect n1,n2,...` (new). Exit 0 only when every expected name is present and passed (a parametrised name requires every `name[...]` instance passed) and no other testcase in the file is skipped, failed or errored. Exit 1 on a skip, failure, error, missing name, empty suite, missing or unparsable junit file, or empty `--expect`. It prints passed / skipped / failed / errored / missing lists so the offending test names are visible in the CI log.
- `.github/workflows/rls.yml`: all three proof steps now write `--junitxml` and are each followed by a checker step with an explicit expected list. The GH-04 inline heredoc is replaced by the script with the same four expected names. Header updated.

## Invariant

Every step of the RLS Proof job that claims a proof is followed by a check that fails unless each named proof test PASSED.

## Tests

`tests/packaging/test_check_junit_all_passed.py` (13 tests) runs the real script as a subprocess and asserts its exit code and printed output:

- hand-built junit: all passed (exit 0, no false positive), parametrised instances all passed (exit 0), one skipped, all skipped (the DSN-empty shape), one missing, one failed, one error, empty suite, missing junit file, empty `--expect`, unexpected skip in the same file (each exit 1 and names the test).
- end to end: the RLS deny module run by pytest with `DMS_LEDGER_DSN=""` exits 0, and the checker on its junit exits 1.
- end to end no-false-positive: a genuine all-green pytest run is accepted (exit 0).

Fails on base: all 13 (the script does not exist at 4f74c0f; verified by removing it and running the module: 13 failed).

## Verified vs assumed

- VERIFIED locally, with a throwaway Postgres 16 on a local DSN and the CI command lines (via `python -m pytest`): RLS deny 1 passed, checker 0; Postgres ledger 4 passed, checker 0; multi-process 2 passed, checker 0. So a green live run keeps the job green.
- VERIFIED: DSN empty, RLS step pytest exit 0 and checker exit 1; Postgres ledger step with no DSN, checker exit 1.
- VERIFIED: with DSN set but sqlalchemy made unimportable, the RLS test reports error (pytest exit 1) and the checker also exits 1. With a genuinely absent sqlalchemy (`ModuleNotFoundError`) `importorskip` produces a skip, which the checker rejects (covered by the skipped cases).
- VERIFIED: workflow YAML parses and the step commands render as intended.
- ASSUMED: GitHub Actions runs the edited workflow as rendered (not executed on Actions from this lane). Locally the bare `pytest` console script points at a different interpreter than `python`, so local simulation used `python -m pytest`; in CI `setup-python` makes them the same.
