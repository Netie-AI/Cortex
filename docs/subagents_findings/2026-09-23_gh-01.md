# GH-01 PII-DAG: redact prompt and system text at the routed-completion choke-point (#241)

- **Date:** 2026-09-23
- **Keywords:** pii, redaction, mykad, nric, dag, llm_judged, agent_task, invoke_routed_completion, C2 boundary, redact port, fail closed
- **Main idea:** `invoke_routed_completion` is the only model-call path for `llm_judged` and `agent_task` nodes and sent `adapter_req.system` and `adapter_req.prompt` raw. It now runs both through an engine-owned redactor port (`CortexOS/security/redact_port.py`) before cost estimation and before `adapter.complete`. The engine default (NRIC, MyKad, email, card) is always on; a pack may register a fuller redactor; a redactor that raises aborts the call with a `status='error'` ledger row and zero adapter calls. `packs/dms/security/pii.py` reuses the engine patterns and gains MyKad.
- **Verify:** `python -m pytest tests/test_execution/test_dag_pii_redaction.py -q -p no:cacheprovider` (23 tests) then `python -m pytest tests/ -q -p no:cacheprovider`
- **Does not prove:** that any pack registers a redactor at runtime (registration from `packs/dms` is out of scope per the PRD; the engine default covers the path without it); phone redaction on the DAG path (deliberately excluded from the engine default, see Risks in the PRD); NER or token-vault behaviour.
- **Cite:** epic #240, PRD `docs/strategy/EPIC_GOVERN_HARDEN_PRD_2026-09-23.md` problem 1 and coordinator amendment.

## Expected vs actual

- Expected (governance promise): sensitive data in a DAG context never reaches a model. A DAG whose `llm_judged` prompt renders an NRIC, a MyKad and an email produces an adapter request carrying `[REDACTED:nric]`, `[REDACTED:mykad]`, `[REDACTED:email]`.
- Actual before this change: `CortexOS/execution/executor.py` built `prompt_blob` from the raw system and prompt and passed `replace(adapter_req, model=routed.model)` straight to `routed.adapter.complete`. `redact_for_prompt` existed only in `packs/dms/security/pii.py`, which the executor cannot import (C2). The pack regex also matched only the Singapore NRIC, so a Malaysian MyKad (`900101-14-5678`) was not redacted anywhere.
- Actual after: the spy adapter in the new test receives placeholders for all three values in both `prompt` and `system`, the `DAGResult.outputs["j1"].output["content"]` echoes placeholders only, and `qty 12` survives unchanged. A registered redactor that raises leaves `spy.requests == []` and one `records_for_run` row with `status == "error"`.

## Repro

Before the change, this test would fail on the first raw-value assertion:

```
python -m pytest tests/test_execution/test_dag_pii_redaction.py::test_run_dag_llm_judged_redacts_context_pii_in_request_and_output -q
```

The DAG is a single `llm_judged` node (`default_tier` T3, `provider` BIG_API_PLACEHOLDER) whose prompt template is `Review customer record: {customer}` and whose context seed carries `S1234567D / 900101-14-5678 / jane@example.com ordered qty 12`.

## Root-cause class

Missing choke-point control. The redactor was implemented on the pack side and applied on the chat and tool paths (`ponytail/middleware.py`, `tool_runner.py`, both on the C2 allowlist) but never on the DAG model-call path, because the boundary rule forbade the obvious import and no port existed.

## Invariant applied

- CortexOS never imports `packs.*`. The port is declared on the engine side in the same shape as `CortexOS/audit/ledger_registry.py` (register / clear / registered / active). `packs/dms/security/pii.py` now imports the engine (allowed direction) and keeps its public API (`PiiSpan`, `detect`, `redact_for_prompt`). Nothing was added to `_C2_ALLOWLIST`; a test in the new file parses both engine files with `ast` and asserts no `packs` import.
- Fail closed. There is always an active redactor (engine default when none registered). A raising redactor becomes `RedactionFailed` (chained), the executor writes a `status='error'` ledger row and re-raises before any cost estimate or adapter call. A redactor returning a non-string is treated the same way.
- T0 is untouched: it never calls an adapter, so the redactor is not consulted there (asserted).
- Over-redaction guard: the engine default excludes the broad phone regex; `qty 12`, `2026-09-23`, `1234.56` and `91234567` survive the default (asserted). The pack keeps phone on top of the engine patterns, so `tests/dms/test_f7_security.py` still sees `[REDACTED:phone]`.

## Changes

- `CortexOS/security/redact_port.py` (new): patterns `NRIC`, `MYKAD` (with and without dashes, place-of-birth code validated, digit lookarounds so a 13+ digit run is not split), `EMAIL`, `CREDIT_CARD`; `detect_spans`, `apply_spans`, `default_redact`; `PromptRedactor` Protocol; `register_redactor`, `clear_redactor`, `registered_redactor`, `active_redactor`, `redact_prompt_text`; `RedactionFailed`.
- `CortexOS/execution/executor.py`: after the T0 early return, `adapter_req` is replaced with redacted `system` and `prompt` inside a try; `RedactionFailed` writes the error row and re-raises. Cost estimation now sees the redacted blob.
- `packs/dms/security/pii.py`: imports the engine port, adds `("mykad", MYKAD)` between `nric` and `credit_card`, delegates `detect` and `redact_for_prompt` to the engine helpers.
- `tests/test_execution/test_dag_pii_redaction.py` (new, 23 tests).
