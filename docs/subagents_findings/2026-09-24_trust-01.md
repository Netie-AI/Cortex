# TRUST-01: auth port and role gates for /api/apps and /api/connectors (#257)

Epic #256. PRD: `docs/strategy/EPIC_TRUST_01_PRD_2026-09-24.md`. Base: 4f74c0f.

## Expected vs actual (before this change)

- Expected: a caller with no key gets 401 on every app and connector route. A key whose role is too low gets 403. Neither changes any state.
- Actual: `CortexOS/api/app_routes.py` and `CortexOS/api/connector_routes.py` had no auth dependency at all. Any caller that could reach the port could import, approve and start an app, dispatch work, and read the workspace catalog (which includes host paths). A malformed import body with no key got 400 from the handler instead of 401.

## Root-cause class

Missing authorization on an engine route plane. The engine had no way to reach the RBAC in `packs/dms/security/api_auth.py` without importing `packs.*`, which the C2 boundary forbids for these two files (they are not in `_C2_ALLOWLIST`), so the routes were simply left open.

## Fix

- `CortexOS/security/auth_port.py` (new): the engine side of the seam. A `RequestAuthorizer` Protocol, `register_authorizer` / `clear_authorizer` / `resolve_authorizer`, and a `require_role(min_role)` FastAPI dependency. Same inversion as `CortexOS/audit/ledger_registry.py` and `CortexOS/security/redact_port.py`.
  - No registered authorizer: 503 with a fixed body. The handler never runs.
  - Authorizer raises anything other than `HTTPException`: 503 with a fixed body (no exception text, so no host paths).
  - The engine re-checks the role the authorizer returns, so a buggy authorizer cannot grant more than was asked.
  - An unknown role name fails at declaration time.
- `packs/dms/security/api_auth.py`: `DmsRequestAuthorizer` reuses the existing `get_caller` and `require_role` (same keys, Bearer support, `DMS_AUTH_DISABLED`, RLS context), and registers itself on import. `create_app` always imports this module through the existing allowlisted route modules, so the authorizer is present in every running app.
- `CortexOS/api/app_routes.py`: viewer for `GET /api/apps` and `GET /api/apps/{id}`; steward for import (zip), reject, rescan, stop, dockerize; admin for import-folder (reads the host filesystem), approve and start (the code-execution chain) and delete.
- `CortexOS/api/connector_routes.py`: the router carries a viewer dependency, so every route (including the HTML desk) needs at least viewer. Steward for posting agent messages, dispatch, opening a Cursor chat and instruct. Admin for computer-control invoke.
- Handlers are unchanged, so a caller with a sufficient role gets the same status and body as before.

## Invariant

Every route under `/api/apps` and `/api/connectors` refuses before its handler runs unless the registered authorizer grants the route's minimum role. No authorizer means refuse. CortexOS still imports no `packs.*` (the arrow points packs to CortexOS).

## Known limitation (not a regression for key-holding callers)

The operator desk HTML at `GET /api/connectors` and its inline `fetch` calls send no `X-API-Key`. With auth enabled, opening it in a plain browser tab now gets 401. It still works with `DMS_AUTH_DISABLED=1` (local dev) or from any client that sends the header. The `/cortex` session cookie is scoped to `/cortex`, so it does not reach this path. A follow-up can give the desk a key field or a cookie scoped to it; that needs a decision on cookie scope and is out of this ticket.

Default auth stays fail-open when `DMS_API_KEYS` is unset (demo keys are accepted). That is the PRD non-goal API-AUTH-05 and was not changed.
