# GH-03 PAR-CEIL: cumulative cost gate for parallel DAG batches (#243)

- **Date:** 2026-09-23
- **Keywords:** dag_runner, run_dag, parallel, asyncio.gather, workflow ceiling, cost ledger, fan-out, overspend, fail closed, GH-03, EPIC-GOVERN-HARDEN
- **Main idea:** `run_dag` gated each sibling in a parallel layer on its own, so N siblings each projected under the remaining budget all passed and the layer overspent the workflow ceiling. A per-batch cumulative gate now sums `estimate_node_cost` over the batch against the ledger total at the moment the batch starts and refuses the whole batch before any sibling calls an adapter. Sequential execution is unchanged.
- **Verify:** `python -m pytest tests/test_execution/test_parallel_cost_ceiling.py -q -p no:cacheprovider` (5 tests) then `python -m pytest tests/ -q -p no:cacheprovider`
- **Does not prove:** overspend on a live provider (reproduced with a yielding stub adapter only); cost accuracy of `estimate_node_cost` (the projection is what it was; the gate only sums it); any Postgres-backed ledger behaviour (in-process `CostLedger` only).
- **Cite:** `docs/strategy/EPIC_GOVERN_HARDEN_PRD_2026-09-23.md` problem 3; issue #243 acceptance criteria.

## Expected vs actual

- Expected (PRD, issue #243): a parallel batch whose summed projection plus the ledger total breaches the workflow ceiling is refused before any sibling spends; the cost ledger holds no rows for that batch and no adapter is called.
- Actual before (baseline 7e14ec1): `run_dag` called `_gate_cost` per node (`0 + 1.0 <= 2.0` passes for each of three siblings), then ran the layer under `asyncio.gather`. The per-call check in `invoke_routed_completion` (`CortexOS/execution/executor.py:99`) read a ledger total the siblings had not yet added to, because `ledger.add` runs after `adapter.complete`. Reproduced: with a 2.0 MYR ceiling and three 1.0 MYR siblings, the adapter received 3 calls and the ledger total reached 3.0 MYR.
- Actual after: the same run raises `WorkflowCostCeilingExceeded` naming the batch (`s1, s2, s3`), the projected 3.0 MYR and the 2.0 MYR ceiling; the adapter received 0 calls; `records_for_run` is empty; `total_cost` is 0.0.

## Repro

Run the new test file against the baseline `dag_runner.py`:

```
git show 7e14ec1:CortexOS/execution/dag_runner.py > CortexOS/execution/dag_runner.py
python -m pytest tests/test_execution/test_parallel_cost_ceiling.py -q -p no:cacheprovider
# FAILED test_parallel_batch_refused_before_any_sibling_spends
#   AssertionError: assert ['sibling s1', 'sibling s2', 'sibling s3'] == []   <- 3 adapter calls under a 2.0 ceiling
# FAILED test_max_parallel_batches_are_gated_with_running_total
git checkout CortexOS/execution/dag_runner.py
```

Note on the stub: the adapter in the test yields once (`await asyncio.sleep(0)`) inside `complete`. With a stub that never yields, `asyncio.gather` effectively serialises the siblings and the per-call check in the executor catches the third one after 2.0 MYR is spent (partial spend, `CostCeilingExceeded`). With a yielding adapter, which is what any network adapter is, all three pass the per-call check and the run overspends. Both are wrong; the yielding case is the one the PRD names.

## What changed

`CortexOS/execution/dag_runner.py` only (issue write target):

- New `_gate_batch_cost(batch, context, router, ledger, wf)`: sums `estimate_node_cost` over the batch and calls the existing `ledger.enforce_ceiling(run_id, wf, projected_additional_myr=sum)`. On refusal it raises `WorkflowCostCeilingExceeded` with the batch node ids, the projected sum, the current ledger total and the ceiling.
- In `run_dag`, inside the `parallel and len(layer) > 1` branch, the gate runs once per batch immediately before `asyncio.gather`, after the abort check, so a second batch (when `max_parallel` splits a layer) is gated against the ledger total that includes the first batch's actual spend.
- The existing per-node `_gate_cost` loop at the top of each layer is kept for both modes. The sequential branch is untouched.

No change to `CortexOS/routing/cost_ledger.py`, `CortexOS/execution/executor.py`, or any do-not-touch path. No new imports.

`tests/test_execution/test_parallel_cost_ceiling.py` (new, 5 tests), all asserting on the run result, the spy adapter call log and the ledger rows:

| Test | Asserts |
|---|---|
| ceiling 2.0, parallel | raises `WorkflowCostCeilingExceeded`; 0 adapter calls; no ledger rows; total 0.0; message names all three siblings and the ceiling |
| ceiling 3.0, parallel | 3 outputs with content `ok` and cost 1.0 each; 3 adapter calls; 3 `ok` ledger rows; total 3.0 |
| ceiling 2.0, parallel=False | unchanged: s1 and s2 spend, s3 raises `CostCeilingExceeded` from the executor; 2 adapter calls; rows `[s1, s2]`; total 2.0 |
| ceiling 2.0, parallel, max_parallel=2 | batch `[s1, s2]` runs and spends 2.0; batch `[s3]` refused with no call and no row; message names `s3` |
| no ceiling, parallel | ungated, 3 calls, 3 outputs |

## Root-cause class

Time-of-check to time-of-use across concurrent siblings: the gate read a shared running total that is only updated after each sibling's spend, so concurrent checks all saw the pre-batch value. Class: check-then-act race on a cumulative counter. Fixed by moving the check to the one place that sees the whole batch before it starts, rather than by adding reservations to the ledger (which would touch `cost_ledger.py`, a GH-03 do-not-touch file, and is queued as COST-NODE-ALL).

## Which invariant applies

- Fail closed: a batch is refused as a whole before any sibling spends; a refusal never leaves partial rows for that batch. Stricter than before by design (PRD risk "GH-03 stricter refusals").
- C2 boundary: `dag_runner.py` gained no imports; `lint-imports` 3 kept, 0 broken; `tests/contract` 95 passed.
- Contract: none. `contract/` and `cortex_contract` untouched; `scripts/check_versions.py` OK.
- Manifest: `CortexOS/execution/manifest.py` untouched.

## Verified vs assumed

Verified:
- Overspend on baseline (3 calls, 3.0 MYR on a 2.0 ceiling) with the yielding stub adapter, via the repro above.
- All five acceptance behaviours in the table above pass on the fixed file.
- Sequential behaviour byte-for-byte unchanged in code (only the parallel branch was edited) and asserted by the `parallel=False` test, which produces the same `CostCeilingExceeded` on baseline and after.
- `tests/test_execution/test_dag_runner.py` (8 tests, includes the concurrency overlap test) still green.
- Gate results are in the commit report.

Assumed:
- That `estimate_node_cost` is a reasonable upper bound for a sibling's spend. If it under-projects, the executor's per-call check remains the last line and the same race as before applies to the under-projected remainder. That is a projection accuracy question, not a gating one, and is outside this ticket.
- Behaviour with a Postgres-backed ledger across workers: `hydrate_run_total` runs once at run start; a second worker on the same run_id is not gated by this change. Out of scope (single-process `run_dag`).

## Not done

- No reservation or hold concept in `CostLedger` (do-not-touch; queued as COST-NODE-ALL / DAG-RESUME-COST per the PRD amendment).
- No event emitted on batch refusal beyond the raised exception; `on_event` consumers see the exception through the caller as before.
- Pre-existing `ruff` (84 findings, none in the two touched files) and `mypy` (41 errors in 26 files, none in the touched files) are outside this ticket.
