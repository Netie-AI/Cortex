# TRUST-03: ABSTAIN provenance clears contributing_sources and drillthrough (#259)

Epic: #256 EPIC-TRUST-01. Base: 4f74c0f. Severity: medium.

## Expected vs actual

Expected: when the badge the customer receives is Badge.ABSTAIN (or BLOCKED), the
enriched `/v1/contract/ask` envelope carries `contributing_sources == []`,
`drillthrough_token is None` and `sql_used is None`. A confident envelope
(`governed_metric`, `certified`, and the other mapped tokens) keeps its sources
and, when SQL is present, a minted drillthrough token.

Actual on base: `_provenance_from_flat` correctly maps an unrecognised badge token
(`document`, `catalog`, `sql_not_analyzable`, empty) to Badge.ABSTAIN, but
`_enrich_answer` decided whether to fill sources and mint a token by calling
`_is_abstain_signal`, which only knows the raw tokens `abstain`, `blocked`,
`refused`, `needs_clarification`. A document answer therefore left the engine
with an abstain badge next to a list of warehouse tables and a drillthrough token
that re-derives rows the answer did not use. The same gap applied when a caller
pre-set `provenance` to ABSTAIN or BLOCKED while the flat tokens looked confident.

## Root-cause class

Two sources of truth for one decision. The badge was resolved once (into
provenance) and then a second, weaker classifier was consulted for the dependent
fields. Any token that only the first classifier knew about slipped through.

## Fix (CortexOS/api/contract_routes.py)

- New `_resolved_badge(data)` reads the badge from the settled `provenance`
  whether it is a `Provenance` model, a dict, or an object with a `badge`
  attribute. Unreadable provenance returns None (no guess).
- New `_is_not_confident(data)`: true when either the raw tokens say abstain or
  blocked, or the resolved badge is ABSTAIN or BLOCKED.
- `_enrich_answer` uses `_is_not_confident` for the sources, drillthrough and
  sql_used decisions. Provenance resolution itself is unchanged, so badges do
  not move; only the dependent values do. No field is added or removed, so no
  contract bump.

## Invariant

An envelope whose provenance badge is ABSTAIN or BLOCKED never lists warehouse
sources and never carries a drillthrough token or SQL. A confident badge with
granted sources always lists them, and with SQL always mints a token.
