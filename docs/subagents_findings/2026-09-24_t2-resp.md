# T2-RESP: no host paths in app and connector responses; archive import limits (#263)

Epic #263 (EPIC-TRUST-02), ticket T2-RESP. Base: 636e99b. Follows TRUST-01 (#256, #257), whose auth port and role gates on these two route files are reused unchanged.

## Expected vs actual (before this change)

- Expected: no response from `/api/apps/*` or `/api/connectors/*` carries an absolute host path, even for an authorized caller. An uploaded app archive is refused, with no trace on disk, when it is too large (on the wire or expanded), has too many entries, or names a member that is absolute or climbs out of the extraction root. A normal archive still imports.
- Actual:
  - Every app record in a response carried `dir` (the install directory on the host), and the built-in Constructor record's manifest carried `skin_dir`. `dockerize` returned the absolute path of the written Dockerfile. Start errors quote whatever the OS or build tool printed, which can include absolute paths, and the 409 detail passed that through.
  - `GET /api/connectors/workspaces` returned each workspace's `root` and `windows_default`; `dispatch` and posting an agent message returned `workspace_root`.
  - `import_zip_bytes` had no size or entry limit (only the folder import did). A member that climbed out of the extraction root was silently skipped and the import still succeeded, and the extractor's containment check is a string-prefix compare, so a name that climbs out and back into a sibling directory sharing the prefix was not caught by it. A body that was not a zip still left an `incoming/` directory behind.

## Root-cause class

Internal state serialized straight onto the wire (store rows and helper results returned as-is), plus trust in an archive's central directory without limits at the import boundary.

## Fix

- `CortexOS/api/app_routes.py`: every app route returns through `_public()`, which drops `dir` and `skin_dir` and redacts known host roots (apps root, data root, repo root, skin dir, temp dir, home) inside any string. Error fields (`error`, `last_error`, `explained_error`, `detail`) and HTTP error details also get a generic absolute-path pass (POSIX, drive-letter and UNC). The generic pass is kept off ordinary fields, which legitimately hold URL paths such as `launch_path`. `dockerize` reports the Dockerfile path relative to the app. The import route refuses an oversize base64 body before decoding it. The helper is exposed as `scrub_host_paths` so the connector routes reuse it.
- `CortexOS/api/connector_routes.py`: workspace rows, dispatch results, the agent-post `dispatch` field, the computer-control probe and invoke results, and 400/404 details go through the same scrubber, with `root`, `windows_default` and `workspace_root` dropped and the configured workspace roots added to the redaction list. The catalog keeps `present` and `env`, so an operator can still see which workspace is missing and which variable sets it. Message and chat text is what a caller typed and is returned as written.
- `CortexOS/execution/app_store.py`: `check_archive()` runs before anything is written. It refuses an archive over `MAX_ARCHIVE_BYTES`, one whose declared expanded size is over `MAX_ARCHIVE_UNCOMPRESSED_BYTES` (zipfile stops each member at its declared size and checks the CRC, so this caps disk use), one with more than `MAX_ARCHIVE_ENTRIES` entries, and one with any member name that is empty, contains NUL, is absolute, has a drive letter or UNC prefix, or has a `..` component (backslashes normalized, so Windows-style names are refused on any host). The whole archive is refused rather than partly imported. Limits match the folder import (200 MB, 2000 entries) and are module constants. `invalid_zip` now reports the exception type only.
- Role gates are untouched: TRUST-01's `require_role` dependencies, with the same 401/403/503 semantics.

## Invariant

Nothing an app or connector route returns names a directory on the host. The store keeps the real paths; only the wire hides them. An archive is either accepted whole within limits or refused with no row and no file written.

## Tests

`tests/test_api_security/test_resp_hardening.py` (20 tests, all assert HTTP status and body plus stored state):

- Role matrix for every route in both files x (no key, viewer, steward, admin): 401 and 403 with a spy on the app store rows, the files under the apps root, the app runner, the agent inbox and the chat store proving nothing changed; each sufficient role gets the handler's normal status (no false positive). Every response in the matrix is checked for host paths.
- No host path: list and get (including the built-in row), dockerize (relative `Dockerfile`, file written), start error text (stored error still holds the real path for the operator), rescan/approve/stop/reject/import-folder, the workspace catalog, dispatch and agent post. Each also asserts the fields the UI uses are still there.
- Archive limits: oversize on the wire, oversize when expanded, too many entries, seven escaping member forms, a sibling-prefix escape, and a non-zip body, each refused with 400, the expected code and no row or file. A normal archive exactly at all three limits, with subdirectories and a file whose name starts with `..`, still imports as a draft with its files on disk.

## Write-target widening

None. The shared scrubber lives in `app_routes.py` (a write target) and `connector_routes.py` imports it, rather than adding a new module. The extractor in `app_package.py` (not a target) keeps its prefix check; the new pre-check in `app_store.py` refuses every `..` name before extraction runs, so the prefix weakness is no longer reachable from import.
