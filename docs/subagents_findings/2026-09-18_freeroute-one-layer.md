# One FreeRoute layer: armed by OpenVault, scored on what served

- **Date:** 2026-09-18
- **Keywords:** freeroute, openvault, arming, credential, measured-route, served-model, a-0009, generative-ask, crew, #211
- **Main idea:** Cortex #211 shipped a crew-side layer that armed on process-env keys, a local Ollama or a sealed vault's key rows, never left `auto` in production, and called a constant header an identity. The follow-up puts one sync, stdlib-only layer at `CortexOS/integrations/freeroute.py` behind the engine, the DMS pack and Crew: armed only when OpenVault's `/api/freeroute/status` reports reachable + `sealed` False + pooled keys + a spendable non-cortex hop; the credential is an OpenVault-verified `ov_` key or the loopback tier (ratelimit identity `local` is NOT verification, and a 401 disarms only the credential that was sent); the route is measured per task over live hops x OpenVault catalogue, persisted in sqlite, and scored on validator verdicts against the model OpenVault actually **served**, because a requested model is only a preference. Engine generative-ask lost its `gpt-4o-mini` default and now names the OpenVault cause in the customer abstain.
- **Verify:** `python -m pytest tests/test_freeroute_core.py tests/test_openvault_client.py tests/dms/test_l2_freeroute_envelope.py tests/test_crew -q` plus `lint-imports --no-cache` (3 kept). Mutation table (R-0007) in the PR body: 18 mutants, each killed by a named test.
- **Does not prove:** any live `:5000` behaviour (OpenVault was down on this box during the work, so the armed live path is unproven); that OpenVault honours a requested model (it does not - hop order is its own); route quality or any error rate (R-0010; n is far below 300); GitHub CI (local runs only); the DMS #180 numbers, which are cited cross-system as an offline `bind_plan` lane scored by a badge-only judge, not a model score.
