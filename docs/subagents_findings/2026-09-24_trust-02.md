# TRUST-02 (#258): engine-failure fallback abstains when grounding is required

Epic: #256 EPIC-TRUST-01. Severity: critical. Base: 4f74c0f.

## Expected vs actual

- Expected: when `answer_engine.answer` fails on a call made with
  `require_grounding=True` (POST /dms/query, the in-process insights bridge), the
  caller gets an explicit abstain with no rows and no warehouse values.
- Actual (base): `answer_question` sent every non-ManifestError exception to
  `_answer_question_legacy`. That path ignores `require_grounding` and session
  grants and queries the demo warehouse directly. The `grant_kind == "none"` guard
  only runs when the engine returns normally, so an engine failure bypassed it.
  Reproduced here: the legacy path returns 1000 low-stock rows and renders
  "1000 SKU(s) below reorder level:" followed by SKU codes, with no badge.
- Secondary: the legacy RAG branch returned an empty answer with no sources and no
  badge, so a consumer could render it as a served answer.

## Root-cause class

Fail-open exception handler. A degradation path written for availability ("engine
failure must not take the API down") was not re-checked when the grounding gate
was added; the gate lived only on the success path.

## Invariant

A grounded call never returns data the engine did not approve. If the engine
cannot answer, the grounded caller gets an abstain envelope: `rows == []`,
`sql_used is None`, `badge == "abstain"`, and prose that says the engine could
not answer. Exception text is not echoed, since it can quote warehouse values.

## Fix (CortexOS/dms/query_service.py)

- In `answer_question`, the generic exception handler now returns
  `_abstain_engine_failure()` when `require_grounding` is true, and logs the
  failure (exception type plus traceback in the log, not in the envelope).
  Ungrounded callers keep the legacy path unchanged.
- `ManifestError` is imported before the `try`. Previously it was imported inside
  it, so if the engine import itself failed, evaluating `except ManifestError`
  raised and escaped the handler as a 500 instead of reaching the fail-closed
  branch. ManifestError is still re-raised unchanged.
- Legacy RAG branch: when `rag_answer` finds no sources, the envelope is stamped
  `badge: "abstain"` and says no document was found. A matched document is
  unchanged.
- The success path (including the delayed/late legacy bridge and the
  `grant_kind == "none"` early return) is untouched.
