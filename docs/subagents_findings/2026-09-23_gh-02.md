# GH-02 RULES-FLOOR: deterministic tier floors apply after a decision-backend choice (#242)

- **Date:** 2026-09-23
- **Epic:** #240 EPIC-GOVERN-HARDEN. PRD `docs/strategy/EPIC_GOVERN_HARDEN_PRD_2026-09-23.md`
- **Keywords:** judgment model, tier routing, legal floor, birthday floor, kev backend, decision backend, fail closed, cost ledger
- **Main idea:** With a decision backend configured, `JudgmentModel.decide` returned the backend's tier verbatim. The deterministic rules (T0 pin for embedding/intent/sentiment, T3 floor for birthday, T2 floor for legal/financial terms) now run after any backend choice and only ever raise the tier. Rules-only routing is byte-identical to before.
- **Verify:** `python -m pytest tests/test_execution/test_judgment_rules_floor.py -q -p no:cacheprovider` (37 tests) then `python -m pytest tests/ -q -p no:cacheprovider`
- **Does not prove:** a live kev server; kev calibration quality; anything about spend levels in production (floors raise some kev choices to T2, which the PRD names as the documented plan rule).

## Expected vs actual

- Expected (plan, Phase 9): deterministic rules trump the classifier. A request that mentions nric, loan, contract or another `LEGAL_TERMS` entry is served at T2 or above; a birthday request at T3; embedding, intent_classify and sentiment always at T0.
- Actual before (VERIFIED at 7e14ec1, `CortexOS/routing/judgment_model.py:90-94`): with `decision_backend` set and the backend not abstaining, `decide()` returned `Tier(answer.choice)` with no floor. The legal rule (:117-118) and birthday rule (:114-115) ran only inside `rules_decide`. So with `CORTEX_KEV_URL` set, `review this loan agreement` could be routed to T0 or T1 and the ledger row would record it. Regression from KEV-DECIDE (PR #235).
- Actual after: `decide()` computes the backend tier, then calls `apply_rules_floor(req, backend_tier)`. When the floor changes the tier, the reason string names both the backend choice and the override, for example `stub-fixed choice T0 (calibrated=True) overridden by legal/financial floor: T2`. When the backend is already at or above the floor, the decision is returned unchanged (same reason string as before).

## Root-cause class

Missing invariant on a new code path. KEV-DECIDE added a second exit from `decide()` and the deterministic rules were not lifted out of the first one. Class: "policy expressed as a branch order instead of a post-condition". The fix makes the rules a post-condition of every backend result, so a future backend cannot bypass them either.

## Invariant applied

Floors only raise. `apply_rules_floor` compares `TIER_ORDER[chosen] >= TIER_ORDER[floor]` and returns `None` in that case, so a backend can never be lowered by a floor, and a backend can never lower a regulated request below T2 or a birthday request below T3. Fail closed: the T0 pin applies regardless of backend choice because those request types are served without a model. The rules branch (`decision_backend is None`) still returns `rules_decide` directly, asserted byte-identical.
