# KEV-CALIB: outcome labels and a calibration report that refuses below n=300 (#247)

- **Date:** 2026-09-23
- **Keywords:** kev, calibration, labels, decision log, ECE, Brier, temperature, automatable share, INSUFFICIENT, scoreboard predicates, ledger status, #247, #245
- **Main idea:** `CortexOS/decision/labels.py` joins KEV-LOG rows with ledger status and scoreboard predicates into a binary "was the served tier sufficient" label, excluding and counting infrastructure failures; `scripts/kev_calibration_report.py` prints n, exclusions, class balance and, only above n=300 with 30 or more negatives, T (on log p pseudo-logits), ECE, Brier and automatable share at 0.02/0.05/0.10 with an implied threshold. Below that it prints `INSUFFICIENT ... no threshold claim` and exits 2. It never writes config.
- **Verify:** `python -m pytest tests/test_decision/test_labels_and_report.py -q -p no:cacheprovider` (11 tests, all through the real writer and a real subprocess of the script), then `python -m pytest tests/ -q -p no:cacheprovider`.
- **Does not prove:** any calibration number for this repo (the log has n=0 rows here); kev's own quality; that fitting T on log p is the right treatment of a probability-returning backend (stated in the report as pseudo-logits, ASSUMED per the PRD).

Epic #245 EPIC-KEV-LOOP. Base ca1d573 (KEV-LOG). Worktree lane wf_ea572173-de3-3.

## Expected vs actual

Expected (issue #247): decision-log rows joined to outcomes; infra failures excluded and
counted, never labelled 0; a report that states n, exclusions and class balance, refuses
with `INSUFFICIENT` below n=300 or below 30 negatives without printing ECE, Brier or a
threshold, and otherwise prints T, ECE, Brier and automatable share at three budgets.

Actual on ca1d573: `calibration.py` has `fit_temperature`, `ece`, `brier`,
`automatable_share`, `choice_confidence` and `softmax`; `decision_log.read_entries`
reads the JSONL back; nothing joins a decision to an outcome and no script prints a
report. `prior_tier_failures` is read by the rules and never set by any code, so
escalation cannot serve as a label (VERIFIED by grep on ca1d573).

## What was built

- `CortexOS/decision/labels.py` (new, stdlib only, no `packs.*`):
  `build_labels(entries, ledger_records=None, predicates=None) -> LabelSet`,
  `label_entry`, `ledger_status_index`, `scoreboard_predicates(db_path)`,
  `is_infra_error`, `LabelledRow`, `LabelSet`. One observed arm only: the probability
  under test is `probabilities[tier]` from the log row (P of the served tier), reduced
  to the two-class row `(1 - p, p)` with label 1 (sufficient) or 0 (insufficient).
  Outcome authority: ledger status for `(run_id, node_id)` when supplied, else the
  log row's own status; scoreboard `arch_runs.predicates_pass` by `run_id` where
  present turns an `ok` row into 0 on a failed predicate. Exclusions, counted by
  reason: `infra:<ErrorClass>` (CostCeilingExceeded, WorkflowCostCeilingExceeded,
  RedactionFailed, timeout/transport/connect classes), `no_probabilities` (live
  backend rows until KEV-SHADOW threads probabilities through),
  `no_served_tier_probability`, `unknown_status`, `missing_run_or_node_id`.
- `scripts/kev_calibration_report.py` (new): `--log` (default
  `decision_log.log_path()`), optional `--ledger-jsonl` (exported node_executions
  rows) and `--scoreboard-db` (SQLite). Prints `n=`, `excluded <reason>=`,
  `class_balance sufficient= insufficient=`; below 300 rows or 30 negatives prints
  `INSUFFICIENT: ... no threshold claim` and exits 2 with no metric line. Otherwise
  `temperature_note=` (states log p pseudo-logits), `T=`, `ece_raw=`, `ece_scaled=`,
  `brier_raw=`, `brier_scaled=`, three `automatable_share budget= share=
  implied_threshold=` lines, and `config_written=none`. Exit 0. Missing log is
  `INSUFFICIENT`, exit 2, not a traceback. Reuses `fit_temperature`, `softmax`,
  `ece`, `brier`, `automatable_share`, `choice_confidence` unchanged.
- `tests/test_decision/test_labels_and_report.py`: 11 tests. Every synthetic log is
  written through `decision_log.append` under `CORTEX_DECISION_LOG_PATH` and read back
  with `read_entries`; every report assertion is on the stdout and exit code of
  `subprocess.run([sys.executable, scripts/kev_calibration_report.py, ...])`.

## Root-cause class

Missing feedback join: the metric primitives and the log existed on either side of an
outcome that nothing connected, so the 0.5 abstain threshold could not be checked
against anything.

## Invariant

ASSUMED:
- Temperature on `log p` pseudo-logits is meaningful for a probability-returning
  backend (PRD lists this as ASSUMED; the report prints the note every run).
- With no scoreboard link, an `ok` node is "sufficient". The PRD names this label
  noise; the class-balance line and the 30-negative floor are the guard.
- The ledger `error` column holds `str(exc)`, not a class name, so the log row's
  `error_class` is the only source for the infra exclusion; a ledger-only error row
  with no log row is not labelled at all (the join starts from the log).
