## Expected vs actual

Expected (issue #247): decision-log rows joined to outcomes; infra failures excluded and
counted, never labelled 0; a report that states n, exclusions and class balance, refuses
with `INSUFFICIENT` below n=300 or below 30 negatives without printing ECE, Brier or a
threshold, and otherwise prints T, ECE, Brier and automatable share at three budgets.

Actual on ca1d573: `calibration.py` has `fit_temperature`, `ece`, `brier`,
`automatable_share`, `choice_confidence` and `softmax`; `decision_log.read_entries`
reads the JSONL back; nothing joins a decision to an outcome and no script prints a
report. `prior_tier_failures` is read by the rules and never set by any code, so
escalation cannot serve as a label (VERIFIED by grep on ca1d573).

## What was built

- `CortexOS/decision/labels.py` (new, stdlib only, no `packs.*`):
  `build_labels(entries, ledger_records=None, predicates=None) -> LabelSet`,
  `label_entry`, `ledger_status_index`, `scoreboard_predicates(db_path)`,
  `is_infra_error`, `LabelledRow`, `LabelSet`. One observed arm only: the probability
  under test is `probabilities[tier]` from the log row (P of the served tier), reduced
  to the two-class row `(1 - p, p)` with label 1 (sufficient) or 0 (insufficient).
  Outcome authority: ledger status for `(run_id, node_id)` when supplied, else the
  log row's own status; scoreboard `arch_runs.predicates_pass` by `run_id` where
  present turns an `ok` row into 0 on a failed predicate. The ledger join is
  **ordinal**: `ledger_status_index` keeps every record per key in append order and
  `build_labels` pairs the nth log row for a key with the nth ledger record, skipping
  log rows whose class raises before `ledger.add` (`CostCeilingExceeded`,
  `WorkflowCostCeilingExceeded`, which write no ledger record). A key whose counts
  differ has every row excluded as `ambiguous_ledger_join`. Exclusions, counted by
  reason: `infra:<ErrorClass>` (CostCeilingExceeded, WorkflowCostCeilingExceeded,
  RedactionFailed, timeout/transport/connect classes, and the litellm
  provider-availability classes RateLimitError, ServiceUnavailableError,
  InternalServerError, BadGatewayError, APIError, APIConnectionError, APIStatusError,
  OverloadedError, HTTPStatusError, Timeout, AuthenticationError,
  PermissionDeniedError, BudgetExceededError), `infra:ledger_error` (paired ledger
  record is `error` and its `str(exc)` text matches infra: timeout, connection, rate
  limit, overloaded, service unavailable, ceiling, redaction, or an HTTP 429/500/502/503
  introduced as a status code), `ambiguous_ledger_join`, `no_probabilities` (live
  backend rows until KEV-SHADOW threads probabilities through),
  `no_served_tier_probability`, `unknown_status`, `missing_run_or_node_id`.
- `scripts/kev_calibration_report.py` (new): `--log` (default
  `decision_log.log_path()`), optional `--ledger-jsonl` (exported node_executions
  rows) and `--scoreboard-db` (SQLite). Prints `n=`, `excluded <reason>=`,
  `class_balance sufficient= insufficient=`; below 300 rows or 30 negatives prints
  `INSUFFICIENT: ... no threshold claim` and exits 2 with no metric line. Otherwise
  `temperature_note=` (states log p pseudo-logits), `T=`, `ece_raw=`, `ece_scaled=`,
  `brier_raw=`, `brier_scaled=`, three `automatable_share budget= share=
  implied_threshold=` lines, and `config_written=none`. Exit 0. Missing log is
  `INSUFFICIENT`, exit 2, not a traceback. Reuses `fit_temperature`, `softmax`,
  `ece`, `brier`, `automatable_share`, `choice_confidence` unchanged.
- `tests/test_decision/test_labels_and_report.py`: 17 tests. Every synthetic log is
  written through `decision_log.append` under `CORTEX_DECISION_LOG_PATH` and read back
  with `read_entries`; every report assertion is on the stdout and exit code of
  `subprocess.run([sys.executable, scripts/kev_calibration_report.py, ...])`.

## Verifier findings on 58f20dd (both blocking, both reproduced, both fixed)

1. **Last-record-wins ledger join.** `agent_task.py` loops `for step in range(max_steps)`
   and calls `invoke_routed_completion` with the same `run_id` and `node.id` on every
   step, so one log row and one ledger record land per step under one key.
   `ledger_status_index` kept only the last record and `label_entry` overrode every
   row's status with it. Repro (`/tmp/kev_probe.py`, log ok,ok,ok,ReadTimeout with
   ledger ok,ok,ok,error): `n 3 neg 3 [(0,'ledger_status')]*3`, three successful steps
   labelled 0 from a timeout. Reverse (log ValueError,ok; ledger error,ok): `neg 0`, a
   real failure erased. After the fix: `n 3 neg 0 excluded {'infra:ReadTimeout': 1}`
   and `n 2 neg 1 [(0,...),(1,...)]`. Fix: ordered list per key, ordinal pairing,
   `ambiguous_ledger_join` on a count mismatch, and the infra check applied to the
   paired ledger record's error text (`infra:ledger_error`). Tests:
   `test_multi_step_node_pairs_each_attempt_with_its_own_ledger_record` (asserts the
   report's `class_balance sufficient=3 insufficient=0` line and
   `excluded infra:ReadTimeout=1`), `test_failure_then_success_keeps_the_failure`,
   `test_ledger_infra_error_text_is_excluded_not_label_zero`,
   `test_mismatched_ledger_count_is_ambiguous_not_last_status`,
   `test_cost_ceiling_rows_do_not_consume_a_ledger_record`.
2. **Provider-availability errors labelled 0.** `is_infra_error` returned False for
   `RateLimitError`, `ServiceUnavailableError`, `InternalServerError`,
   `APIStatusError`, `HTTPStatusError`, `OverloadedError`, so a 429/503 outage window
   would have injected false negatives and moved T and the implied threshold. The
   adapters call `litellm.acompletion` directly, so those litellm class names are
   exactly what reaches `decision_log.build_entry`'s `error_class`. Fix: added them
   (plus `BadGatewayError`, `APIError`, `APIConnectionError`, `Timeout`,
   `AuthenticationError`, `PermissionDeniedError`, `BudgetExceededError`,
   `MidStreamFallbackError`) to `INFRA_ERROR_CLASSES` and `RateLimit`, `Overloaded`,
   `ServiceUnavailable`, `InternalServer`, `BadGateway`, `Unavailable` to the substring
   net. Content/validation failures (`ValueError`, `JSONSchemaValidationError`,
   `ContextWindowExceededError`, `BadRequestError`) stay label 0 and are asserted so.
   Tests: `test_provider_availability_errors_are_infra_not_label_zero` (asserts the
   report's `excluded infra:RateLimitError=4` and class-balance lines) and an
   exclusion-count assertion (`sum(excluded) == 15`, `n + excluded == total_entries`)
   added to `test_infra_errors_are_excluded_and_counted`.

All 6 new tests fail on the 58f20dd `labels.py` (checked by swapping the file back in:
6 failed, 11 passed) and pass with the fix.

## Root-cause class

Missing feedback join: the metric primitives and the log existed on either side of an
outcome that nothing connected, so the 0.5 abstain threshold could not be checked
against anything.

## Invariant

- The report never writes config and never reads or changes
  `CORTEX_DECISION_ABSTAIN_THRESHOLD`; the test sets the env to 0.42, runs the report
  and asserts the env, `default_abstain_threshold()` and the served
  `JudgmentModel().decide()` are unchanged.
- No metric below n=300 or below 30 negatives: `INSUFFICIENT`, exit 2, and the test
  greps stdout for `ece_`, `brier`, `T=`, `implied_threshold`, `automatable_share`.
- Infra failures are never label 0: they are excluded and counted by class, from the
  log row's own class and from the paired ledger record's error text.
- The ledger join never lets one attempt's status stand in for another: pairing is
  ordinal per key and a count mismatch is excluded, not guessed.
- No prompt text: the log carries none; the report prints only counts and metrics;
  the test plants a token in the hashed state and asserts it is absent from stdout.
- `CortexOS/**` never imports `packs.*` (lint-imports 3 kept, contract tests 95 pass).
- Do-not-touch respected: no change to `decision_log.py`, `calibration.py`,
  `CortexOS/routing/**`, `CortexOS/execution/**`, `tests/contract/**`,

ASSUMED:
- Temperature on `log p` pseudo-logits is meaningful for a probability-returning
  backend (PRD lists this as ASSUMED; the report prints the note every run).
- With no scoreboard link, an `ok` node is "sufficient". The PRD names this label
  noise; the class-balance line and the 30-negative floor are the guard.
- The ledger `error` column holds `str(exc)`, not a class name, so the infra check on
  the paired ledger record is a text match (fragment list plus an HTTP-status regex),
  not a class match; a ledger-only error row with no log row is not labelled at all
  (the join starts from the log).

  pairing depends on it. Only `CostCeilingExceeded` and `WorkflowCostCeilingExceeded`
  raise before `ledger.add` (VERIFIED by reading `invoke_routed_completion`); any
  other future pre-ledger raise would show up as `ambiguous_ledger_join`, which is
  counted and printed, not silently mislabelled.
