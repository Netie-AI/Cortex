## Repro

The harness, adapter and run files were scratch-only; see P1 section 6 for the hashes. Run command:
```
OV_DAILY_TOKEN_CAP=15000000 OV_DAILY_REQUEST_CAP=6000 python3 -I bird_adapter.py run --client ov --live --max-tokens 2048 --label bird_minidev_r2 --resume
```
Route: local OpenVault FreeRoute, `ov_` eval key, strict pin `moonshotai/kimi-k3`, served by NVIDIA on 498/498 rows. Model SQL runs on DuckDB mirrors of BIRD's SQLite databases; gold runs on SQLite.

## Root-cause class

1. **Output contract mismatch.** 74 of 222 WRONG have the right values in the wrong shape (extra ranking or key columns, key instead of name, x100). The frozen prompt asks for the measure and key; BIRD's gold wants neither. A shape check refuses these, so for a product user it refuses right answers. Fix the contract or re-ask with the defect named, not a bare refusal.
2. **Semantic error in clean 1x1 answers.** The 17 truly-wrong answers that pass every check are mostly one row by one column: counting rows instead of distinct entities, a different filter reading, a different formula. No shape, process or schema check can see them. The untested next candidate is a grain probe (COUNT vs COUNT(DISTINCT)), which has to be chosen on A and confirmed on a fresh split.
3. **Large schema context breaks the model's output.** All 10 ERRORs are in `european_football_2` (88k-char schema context): leaked chat-template tokens after the re-asks.

## Invariants that apply

- **Don't claim "0 wrong" below n=300 / rule of three.** The 3/n bound applies only where WRONG=0, which never happens here.
- **Silent fallback is a lie.** Deviations (2048 token clamp, strict pin, DuckDB mirror, pro tier, raised client guard, resumed chunks) are recorded in P1 section 5, not hidden.
- **Separate verified fact from assumption.** P1 section 9 and P2 sections 2 and 8.
