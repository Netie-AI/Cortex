# T2-CTRL-B: role gates on the workflow, DAG-run and activity routes (#263)

Epic #263 (EPIC-TRUST-02), follows TRUST-01 (#256, #257). Base: 636e99b. No contract impact (none of these paths is in `contract/openapi-*.json`).

## Expected vs actual (before this change)

- Expected: every route in `CortexOS/api/workflow_routes.py`, `CortexOS/api/dag_run.py` and `CortexOS/api/activity_routes.py` refuses a caller with no key (401) or too low a role (403) before its handler runs, with no side effect. A missing authorizer refuses with 503.
- Actual: none of them had an auth dependency. Any caller that could reach the port could start, cancel, resume and wipe background workflow runs, push a hardware profile that changes the runner's parallelism gate, execute an arbitrary inline DAG against the model budget and cost ledger, and read run costs and the engine activity panel.
- Expected: a workflow run records the authenticated caller as its actor. Actual: `POST /api/workflows/run` stored whatever `actor` the request body asserted.
- Expected: a run orphaned by an engine restart reads as interrupted on every read path. Actual: only the tasks panel (`snapshot()`) and `resume()` reconciled orphans. `GET /api/workflows/task/{id}`, its event stream and `GET /api/engine/activity` still reported a dead run as running, and the event stream for such a run never ended (it sent keepalives forever because the row never became terminal).
- Also found while in this file: an activity section that failed echoed the raw exception text into the panel body, which can include a store's host file path.

## Root-cause class

Missing authorization on an engine route plane (same class as TRUST-01), plus trusting a caller-supplied identity field, plus a reconciliation step wired into some read paths but not all.

## Fix

Reuses `CortexOS/security/auth_port.py` exactly as `CortexOS/api/app_routes.py` does (`dependencies=[Depends(require_role(...))]`, same 401/403/503 semantics, no `packs.*` import).

| Route | Role |
|---|---|
| `GET /api/workflows`, `GET /api/workflows/tasks`, `GET /api/workflows/task/{id}`, `GET /api/workflows/task/{id}/events` | viewer |
| `POST /api/workflows/recognize` (pure text classifier, no state) | viewer |
| `POST /api/workflows/run`, `/cancel`, `/resume`, `/hardware` | steward |
| `POST /api/workflows/clear` (deletes run history) | admin |
| `POST /run` (arbitrary caller-authored DAG, spends model budget, writes the cost ledger) | admin |
| `GET /api/engine/runs/{run_id}/cost` | viewer |
| `GET /api/engine/activity` | viewer |

- `POST /api/workflows/run` takes the principal from the same steward dependency and passes `principal.actor` to the runner. The body's `actor` field is still accepted (wire compatibility) and ignored.
- The task read, the event stream and the activity panel's workflow section call the runner's existing once-per-process reaper before reading, the same call `snapshot()` and `resume()` already make. A refused request never reaches the handler, so it never reaps.
- The activity panel returns only the exception class for a failed section and logs the detail server side.
- Handlers are otherwise unchanged, so a caller with a sufficient role gets the same status and body as before.

## Invariant

Every route in these three files refuses before its handler runs unless the registered authorizer grants the route's minimum role. The actor stored on a workflow run is the authenticated caller. No read path reports a run a dead process left behind as live. CortexOS still imports no `packs.*`.

## Known limitation

`CortexOS/crew/connectors.py` probes `GET /api/engine/activity` with no key to decide whether the Cortex engine is "connected". With auth on, that probe now gets 401 and the connector row reads as down. The probe is a liveness check using a data route; the follow-up is to point it at a health route or send the configured engine key. It is outside this ticket's write targets and was not changed.
