# KEV-LOG: append-only tier-decision log from invoke_routed_completion (#246)

Epic #245 EPIC-KEV-LOOP. Base fe839ea. Worktree lane wf_ea572173-de3-1.

## Expected vs actual

Expected (issue #246): every ok, error and T0 outcome of `invoke_routed_completion`
leaves one JSON line an operator can read back, with the tier, reason, backend,
confidence and probabilities when available, status, error class, cost and a
state hash, and never raw prompt text.

Actual on fe839ea: `ModelRouter.route()` returns `RoutedModelCall(tier, provider,
model, reason, adapter)`; the JudgmentDecision confidence is dropped inside `route()`
(CortexOS/execution/model_router.py:56-77) and nothing writes a decision record
anywhere. `node_executions` has tier and status only.

## Root-cause class

Missing observability at a choke point: the decision port existed (KEV-DECIDE) but
its output was consumed and discarded in the same function that produced it.

## Invariant

- The decision log never carries `content`, `prompt` or `system`; `build_entry`
  strips those keys and `append` refuses an entry that carries them. The test plants
  a secret in both prompt and system and greps the file.
- Logging never changes a node result and never raises: `_log_decision` and
  `log_decision` absorb every exception; failures increment `write_failures()`.
- `CortexOS/**` still never imports `packs.*` (lint-imports 3 kept, contract tests 95 pass).
- Do-not-touch list respected: no change under `CortexOS/db/sql/**`, `CortexOS/routing/**`,
  `dag_runner.py`, `tests/contract/**`, `tests/invariants/**`, `.importlinter`, `contract/**`.

## Design decision worth knowing (confidence with a live backend)

`route()` is not a write target and `routing/**` is off limits, so the confidence
cannot be threaded out of `JudgmentModel.decide()` in this ticket. The log therefore:

- re-evaluates rules-v0 through the existing `RulesBackend` when the router has no
  decision backend (pure, free, deterministic): `confidence` and per-tier
  `probabilities` are filled;
- only names the backend when a live decision backend is configured, and records
  `confidence=None, probabilities=None`. Re-asking the backend would double every
  kev call, which the PRD lists as a risk. The test with a counting backend asserts
  exactly one backend call per node. KEV-SHADOW (rules serve, kev evaluated beside)
  is the ticket that produces kev probabilities for the calibration join.
