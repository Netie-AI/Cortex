# Cortex — rules for any agent working in this repo

Cortex is **the engine**: answer plane, execution, ledger, compliance gate, semantic
layer, context assembly. DMS is a consumer app. OpenVault is key custody.

Several lanes work this repo at once — Claude Code, Cursor, and a separate project
that drives DMS. The rules below exist because a change that looks local can break a
boundary another lane depends on, and some of them fail *silently*.

If a rule here conflicts with an instruction you were given, say so before acting.

---

## 1. Hard invariants — never break these

| Invariant | Why |
|---|---|
| `CortexOS/**` must never import `packs.*` | Packs register **into** the engine; the engine only ever holds a port. Enforced by `.importlinter` and `tests/contract/test_import_boundaries.py`. To reach a pack, declare a Protocol on the engine side and have the pack register an implementation — see `CortexOS/audit/ledger_registry.py`. |
| `duckdb` appears only under `CortexOS/execution/` | One place opens the database, so one place can enforce a manifest. |
| DMS must never import `CortexOS` | It is the engine. DMS speaks HTTP through its generated client. |
| DMS **may and should** pin `cortex-contract` as a dependency | The models and the canonicalisation rule must be *the same code*, not two implementations of one spec. `cortex_contract` has zero `CortexOS` imports by its own lint rule, so this does not leak the engine. |
| One ledger | Consumers append through Cortex. Nothing else maintains a hash chain. |
| Engine version and contract version are independent | Engine `2.5.0` tracks G-gates; contract `1.2.0` tracks the wire. `scripts/check_versions.py` fails the build if any code assumes they are equal. |

## 2. Protected paths — a commit body must contain `INVARIANT-CHANGE:`

- `tests/contract/**`
- `tests/invariants/**`
- `.importlinter`

CI has a job that fails the build otherwise. If you are about to edit one of these to
make a test pass, you are almost certainly fixing the wrong thing — the test is the
requirement.

**Specifically: do not add files to `_C2_ALLOWLIST` in
`tests/contract/test_import_boundaries.py`.** That list is pre-C2 debt being
evacuated, and its docstring says new crossings must fail immediately. Note it
matches by **basename**, so `registry.py` silently covers every `registry.py` in the
tree — `.importlinter` is the stricter check, and the one to trust.

## 3. `contract/` — frozen artifacts, never hand-edited, never deleted

```
contract/openapi-1.0.0.json     frozen. A consumer may still be pinned to it.
contract/openapi-1.1.0.json     frozen. Compat / older pins.
contract/openapi-1.2.0.json     current. Generated by scripts/export_openapi.py. DMS pins this.
contract/compat.yaml            which majors/minors this engine still serves.
contract/testvectors/           canonicalisation vectors both repos assert against.
```

- Regenerate with `python scripts/export_openapi.py` (needs `.[full]`), never by hand.
- CI fails on drift, because the spec is the artifact DMS consumes.
- **Deleting a published spec strands anyone pinned to it.** Add, never remove.

## 4. `packages/cortex_contract/` — a field change is a version decision

Models and Protocols only. Zero `CortexOS` imports, ever.

| Change | Version |
|---|---|
| Add a field or endpoint a consumer can ignore | contract **minor** |
| Remove, rename, or retype a field a consumer reads; change an existing field's meaning | contract **major** — a coordinated release, not a commit |
| Fix that does not alter the wire | contract patch |

Additive is cheap, subtractive is expensive. Deprecate alongside instead: keep the old
field, add the new one, remove at a major you were taking anyway. Bump **both**
`version.py` and `pyproject.toml` — they are asserted equal — then regenerate the spec
in the *same commit*, or the drift check breaks the build.

### `canonical_manifest_bytes()` is the most dangerous function in the repo

DMS signs those exact bytes; Cortex verifies them. Change the rule and **every
manifest DMS signs stops verifying**, and it presents as a crypto bug, not a
serialisation bug. Any change is a contract major plus a coordinated DMS release, and
`contract/testvectors/manifest_canonical.jsonl` must be regenerated and re-agreed.

## 5. `CortexOS/execution/manifest.py` is a security control

It decides what a session may read. Two rules:

1. **Never weaken a refusal to make a query work.** The refusals are fail-closed on
   purpose — a query the enforcer cannot fully analyse is one it cannot prove safe. If
   real analytics is being refused, narrow the check; do not remove it.
2. **Re-run the corpus after any change:**
   `python -m pytest tests/test_execution/ -q` (201 tests).

`tests/test_execution/hostile_sql_corpus.json` — cases may be **added**. Never
reclassify a case to `allow_but_predicate_must_apply` to make a test pass. The one
`minting_invariant` case documents a gap Cortex genuinely cannot close; it is asserted
so nobody later reads the corpus as proof that it can.

## 6. Working alongside other lanes

- **Check `git log --oneline -3` before `git commit --amend` or any rebase.** A lane
  fast-forwarded onto main mid-session here and an `--amend` landed on their commit.
  Never rewrite a commit you did not author.
- Stage precise paths. `git add -A` in this repo picks up other lanes' work in progress.
- `.cursor/` is tracked but outside this checkout's sparse cone; it needs
  `git add --sparse`.
- **The project that drives DMS**: talk to Cortex over HTTP through the generated
  client only. Do not vendor or fork `packages/cortex_contract` — pin it. Do not write
  to `contract/`; that directory is produced here and vendored there.

## 7. Verifying, honestly

```bash
python -m pytest tests/ -q                  # see STATUS.md for the current count
ruff check CortexOS packages/cortex_contract scripts tests/packaging tests/contract
mypy
lint-imports                                # NOT `python -m importlinter.cli`
python scripts/check_versions.py
python scripts/export_openapi.py --check    # needs .[full]
```

`python -m importlinter.cli lint` **exits 0 without running any contract** on Windows
here — it prints nothing and looks like a pass. Use the `lint-imports` console script;
if it is not on PATH, it is at
`%APPDATA%\Python\Python3xx\Scripts\lint-imports.exe`. A gate that cannot fail is not
a gate, so check that a command can actually report failure before trusting its exit
code.

## 8. Answer-path tests assert user-visible output

Every test for answer-path behaviour must assert on the **rendered answer text** and
the **returned rows**, not only on generated SQL. SQL assertions are permitted only
*in addition*. A gate that asserts an intermediate artifact will certify a broken
feature as working (see the SKU-BETA / `NOT IN ('BETA')` false verification).

**Value normalization** — filter tokens must resolve to the column's actual encoding
(`BETA` → `SKU-BETA`, location dual-coding, case/whitespace). Prefer abstain over a
filter that matches nothing while the envelope stamps success.

**Customer envelope (Phase 0)** — every gate must also assert on the artifact the
customer receives. Cortex-side assertions are necessary and insufficient. When the
consumer is DMS, assert badge / abstained / values / sources / drillthrough_token /
audit_id on the DMS envelope from `POST /v1/chat/ask` (see DMS
`assert_envelope_valid`). A green badge on abstention prose is a P0.

**C7 (pre-D1)** — replace the keyword cascade in `answer_engine.route_to_metric` with
schema retrieval → generation → sqlglot → EXPLAIN → bounded retry → plausibility.

Runtime state is gitignored and regenerated — `data/engine/`, `data/bench/`,
`data/lakehouse/`, `CortexOS/data/` (holds a per-device key; never commit it), and
`packs/data/dms_ops.db` (rebuild: `python -m scripts.seed_ops_db`).
